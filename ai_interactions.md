## Part 1: VibeMatch's agentic workflow

### The decision chain

For each request, `VibeMatchAgent.run()` in [`src/agent.py`](src/agent.py) plans, acts, checks its own work, and retries:

| Step | Kind | What happens | Can end the run? |
|---|---|---|---|
| `input_guardrail` | check | Blocks empty, oversized (>300 chars), prompt-injection, and off-topic requests | Yes, `blocked` |
| `parse` | tool call (Gemini, or keyword fallback) | Free text becomes `{genre, mood, energy, likes_acoustic}` plus a confidence score | |
| `validate_profile` | check | Clamps and repairs values; drops labels the knowledge base has never heard of | |
| `retrieve` | tool call (TF-IDF retriever) | Finds knowledge notes; returns related genres and moods and an energy hint, each with its source | |
| `fill_missing` | plan | Fills missing energy and acoustic values from retrieved notes, or from defaults if none | |
| `clarify` | decision (human-in-the-loop) | If parse confidence is below 0.45 or there is no genre and no mood, the agent asks the user | Yes, `needs_clarification` |
| `score_and_verify` | tool call + 6 checks | Scores the catalog, then checks its own output. If a check fails, it **retries with the next strategy** (`baseline` → `broaden_retrieval` → `prioritize_energy`) and keeps the best attempt | |
| `explanation_check` | check | A Gemini explanation is rejected if it names a song that was not recommended | |

Every run (all steps) is appended to `logs/vibematch.jsonl`. Regenerate the traces below with:

```bash
python scripts/dump_traces.py          # offline (deterministic)
python scripts/dump_traces.py --llm    # with Gemini
```

## Part 2: How I used an AI coding agent to build this

**Tool:** Claude Code (Claude Opus 5.5), working inside the repository with me reviewing each step.

**What I asked it to do:** extend my Module 3 Music Recommender into an applied AI system, one phase at a time:
(1) RAG knowledge base + retriever, (2) guardrails, Gemini parser and agent loop, (3) evaluation harness, (4) docs.
I asked it to guide me step by step so I could check each piece myself before moving on.

**What it generated or changed:** `knowledge/*.md`, `src/retriever.py`, `src/guardrails.py`, `src/parser.py`,
`src/llm_client.py`, `src/agent.py`, `src/cli.py`, `src/evaluate.py`, `eval/cases.json`, the tests in `tests/`, and the docs.
The commit history shows each phase separately.

**What I verified myself:**
- Ran the retriever on my own queries (`heavy gym music`, `rainy day jazz`, `reggaeton party`, `sleepy piano`).
  `sleepy piano` missed the sleep note entirely. That led to adding stemming, which fixed it (similarity 0.61).
- Ran the CLI (`python -m src.cli`) and the test suite (`pytest`) myself to see the results.
- Created the empty public GitHub repo myself, and learned the `git add` / `commit` / `push` flow along the way (including what "nothing to commit, working tree clean" means).
- Switched from my old Module 3 virtual environment to this project's own `.venv`, and confirmed it with `which python`, so nothing I installed touched my Module 3 submission.
- Copied my Gemini API key from my DocuBot `.env` myself, so the key never passed through the AI assistant.

**Problems the agent's own testing caught** (each one changed the design):
1. The first version passed every check for "Sad but energetic blues", even though the top pick had energy 0.40 against a requested 0.85. We added the `top_pick_energy_fits` check.
2. The first `prioritize_energy` retry then **over-corrected**: it dropped the only sad blues song and recommended happy pop. We added `keeps_requested_label`, so the agent now keeps the best label match and reports the conflict.
3. The agent failed its own energy check on "happy pop" against a default energy the user never asked for. Energy checks now run only when energy came from the user or a retrieved note.
4. In the first Gemini evaluation, "acoustic folk for maximum energy" returned **zero folk songs** while every check passed. Gemini parsed it as `folk + intense`, and the label check accepted the mood match. Now the requested genre must survive, and keeping it outranks every other check when choosing between attempts.
5. The first Gemini evaluation hit the free tier's 15 requests/minute limit. Fallbacks kept every run working, but the report wrongly counted rate-limit errors as "rejected explanations". We added pacing, retry-on-429, and separate metrics.

The accepted and rejected suggestions are discussed in [`model_card.md`](model_card.md#ai-collaboration).
